# 测试范围

在项目根运行 `node --test tests/target-scope.test.mjs`，验证页面切换的 query/hash 识别，并排除认证网站、嵌入网页、其他原生窗口与覆盖层。

`tests/NativeContracts.cs` 与 Common.cs、InstalledClient.cs 一起编译后运行，验证真实子进程参数往返、页面识别和包路径边界。`tests/StartupGuardContracts.cs` 与 Common.cs、StartupWindowGuard.cs 一起编译，使用屏幕外替身窗口检查防闪层、归属标记和样式恢复。测试窗口不属于官方客户端，不是完整启动验收的替代品。

涉及启动、关闭、重载和生命周期的客户端自动化必须使用独立用户数据目录和独立本机端口，先动态保存当前任务父进程链和已有客户端，再验证测试进程的 PID、创建时间、安装路径与明确的测试配置目录。清理前再次验证；禁止向承载当前任务的客户端发送 Esc、停止、关闭或重载。

用户明确授权检查当前客户端时，可使用 `tests/native-client-session.mjs` 的固定菜单检查接口。`client()` 默认只读；只有显式调用 `client({allowMenuInspection:true})` 才能通过 `inspectMenu(action)` 展开已列明的设置页、菜单和执行有限滚动。它不提供任意点击、键盘输入、模型／账号选择、权限修改或表单提交。通用 `call()` 不允许输入与导航协议方法。连接前须另外核实本机端口监听者、官方进程 PID 和启动时间，与 `attachment.json` 一致；此接口的正则检查不是执行不可信代码的安全沙箱。检查脚本仅使用项目维护的固定表达式。

同一明确授权下，`inspectHover(action)` 只向列明的首页、头像、附件、发送及账号菜单项发送鼠标移动，用于检查真实悬浮状态；不会按下鼠标。停止按钮不会成为悬浮检查目标，`clear` 会移走测试悬浮。通用输入协议仍被拒绝。

`inspectWheel(direction)` 仅在未被覆盖的对话滚动区内发送一次受限滚轮事件。真实 OS 滚轮与直接更改 scrollTop 要分别记录；背景窗口直接抓边与先激活后抓边也不能混作同一路径。

缩放实测要覆盖日常默认配置，并分别检查先激活后拖动、直接抓取未激活窗口边缘、四边、四角、按住和快速松手。临时在测试中启用缩放助手的结果不能证明默认启动已修复；黑边像素统计也不能替代对临时预览变形、延迟和清晰度的查看。

缩放预览会在接近边缘时异步抓取目标窗口，以免把系统水印或其他桌面元素拉伸进预览。抓取为空、超时或窗口尺寸已发生变化时，保留原有屏幕截图回退。验收时查看边缘中间帧和辅助器的 `windowCaptures`，并记录实际走到的抓取路径。

实际检查必须等内容和弹层过渡完成，截图并查看。设置返回可能回到首页。已获授权的测试可调用 `inspectMenu('restore-task-thread')`，由宿主提供当前任务 ID，定位侧栏原有会话并恢复。检查恢复后仍为原会话，且任务未被中断。实际画面证据存放私有验证目录，源码导出不包含截图、用户资料或登录数据。

悬浮检查按控件语义覆盖普通按钮、组合框、开关、单选／复选、菜单项、列表行、摘要展开项与图片预览。已有外壳或原生伪元素的控件必须检查是否重复画框、投影和缩放；命中范围、实际显示表面与反光边界分别核对。检查进行中的聊天自动滚动时，侧栏静止按钮应保持悬浮，按钮所在滚动区域移动时应清理旧反光。四档浏览器回归也覆盖这两类滚动场景，但不代替真实客户端实测。

登录、验证码、真实账号与团队权限由用户本人处理；没有登录状态的环境只能验证公开登录页，不能把它标为账号／团队切换已通过。测试不能复制账户缓存或凭据来补足登录条件。

关闭、重开、系统登录启动、崩溃、升级、跨 DPI、多屏、长时间运行与完整视觉逐帧比对均须单独记录。模拟、局部截图、统计数字与源码存在分别说明范围，未验证项保留。

运行 scripts/test-install-kit.ps1 并传入两套完整的发行目录，可在结果目录的独立子目录中验证首装、完整升级、回退、卸载、重装及原有文件的保留。测试不需要登录官方客户端。

`node tests/surface-browser.mjs <Chromium 可执行文件> <新的测试配置目录>` 用独立浏览器配置验证弹层配色、页面切换清理、文字更新和恢复原样。它使用项目自带的通用测试标记，不需要真实账号。

重复回归可在宽高和缩放参数后加 `--reuse-fixture`，复用带有项目专用所有权标记、且记录的浏览器进程已经退出的测试目录，减少反复制造缓存。它拒绝普通浏览器配置和仍在使用的测试目录，不删除任何已有配置。代码查看区回归还检查 Shadow DOM 的语法色、异步新增行与移除皮肤后恢复原生样式。

`scripts/test-contracts.ps1` 统一运行六组原生逻辑测试与 Node 测试。状态文件测试包含并发写入和占用失败保护；保活程序测试覆盖素材暂缺后重试和元数据原子替换；菜单检查测试覆盖滚动超时后的回调取消。这些测试证明对应逻辑，不能代替真实界面和整机性能验收。

安装测试使用独立目录。环境检查按钮在复制前验证官方安装注册、Node 和包文件。WebView2 不可用时提示桌面特效不可用，允许安装客户端皮肤。发行和源码导出流程运行 audit-package.ps1，按包清单检查文件和哈希，并对文本检查选定的路径、配置与凭据模式。媒体内容与分发许可另行核对。

安装器测试可加 `-WithoutDesktopRuntime`，仅对子进程指定不存在的 WebView2 目录，验证安装提示和其他步骤。通过这一测试不代表在未安装 WebView2 的另一台实际电脑完成了验收。

## 官方更新与新功能复测

1. 用 `--diagnose` 记录官方包版本、Windows 登记的入口类型以及是否可以挂载皮肤。当前已复核的包版本由启动器的版本记录维护。对刚更新的版本，先走 Windows 注册的原生入口，检查能否正常启动、唤回已有窗口，以及能否使用原有账号与工作区。
2. 在独立测试配置中核对候选版本。检查冷启动、唤回、登录与回跳、个人和团队工作区、首页、聊天、设置、通知、弹层、缩放、恢复原样和退出。真实登录、回跳和账号状态只在具备用户授权的隔离环境验收。
3. 逐个打开官方新增页面或功能。先记录原生操作路径、焦点、快捷键、权限与恢复行为，再核对皮肤是否遮挡或改变交互。检查陌生页面切回已支持页面时主题自动恢复，以及同一版本内逐步开放的功能。
4. 记录官方版本、适配版本、复测环境、每条路径的结果与证据。更新 `runtime/InstalledClient.cs` 的 `ReviewedVersions` 前，先在私有候选构建完成上述验证。完成回归后再交付匹配的新皮肤。旧皮肤版本适合回退到已经复核的版本组合。

本机合同测试对照已知版本、未复核版本、协议入口变化、登记不唯一，以及旧连接被替换的情况。独立浏览器回归用保留侧栏的陌生页面验证原生样式和返回工作区后的恢复。真实官方升级及后续新增功能分别记录实际结果。

### 新页面和新模块的视觉验收

适配新增界面时，使用 `runtime/spider-theme.js` 中已有的控件圆角、卡片圆角、输入区圆角、暖色高光和动效参数。常规控件用 8px，卡片及弹层用 12px，大输入区用 20px。开关和圆形图标保留各自的原生轮廓。控件内的高光贴合圆角，弹层外框约束高光的显示范围。

- 悬浮时只保留一层高光，弹层行的内容动效在原有命中范围内完成。测试移出、滚动与关闭后的高光清理。按下和选中使用同一套颜色关系。
- 用键盘进入菜单、子菜单和表单，确认焦点清晰，而且在带圆角的边界以内。指针停在同一控件上时，键盘焦点仍清晰可辨。禁用控件保持禁用表现，减少动态效果时保留焦点和反馈。
- 验证常见宽度、窄窗、四档缩放、文字换行和同级弹层的间距。只有在官方组件或模块已识别并通过原生操作与视觉复测后，才把新页面纳入支持范围。

在 `tests/surface-browser.mjs` 的宽高、缩放参数后加 `--native-pointer`，会在独立浏览器里移动实际指针，验证运行时新增菜单的高光裁切、焦点、禁用状态、圆角和子菜单对位。真实官方新增页面仍需通过对应的界面实测。
